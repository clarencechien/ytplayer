# 成本優化計畫（重試效率）

> 狀態：**計畫，未實作**。決策欄在 §7。
> 起因：2026-08-14 一支 9 分鐘英文 ASR 影片（`hK9fypJKHyY`）花 **NT$10.87**，
> 帳目正常（`thoughts=0`、估算＝牌價直算）但拆開後發現**六成是重試造成的重複輸出**。

---

## 1. 實測解剖（不是估的）

| 項目 | 數字 |
|---|---|
| 影片 | 9 分鐘、英文 ASR、274 句 |
| tokens | 78,176（prompt 47,289 / output 30,887 / **thoughts 0** ✅）|
| 呼叫 | **31 次**（理論最低 15：修稿 7 + glossary 1 + 翻譯 7）|
| 重試 | 12（warning：某 chunk 頑固缺 1 句）|
| 成本 | prompt NT$2.22（20%）+ **output NT$8.65（80%）** = NT$10.87 |

**兩個關鍵比值**：

1. **輸出佔帳單 80%**（輸出牌價是輸入的 6 倍）→ **省 input 對帳單幾乎無感，省 output 才有感**
2. **每句輸出 113 tokens**，但一句中文譯文只該 ~35 → **約 3 倍膨脹，差額全是「重試把整包譯文重吐一次」**

推算：若零重試，這支約 NT$4.2 → **NT$6.7（62%）是重試的代價**。

原始素材其實很小：全片原文僅 ~2,500 tokens（每 chunk ~360）。也就是說我們付的錢
幾乎都不在「內容」上，而在「重複」上。

## 2. 病根：重試的粒度是「整個 chunk」

現行 `translateChunk` 的補救鏈，每一步都重付整包 20–40 句的輸入**與輸出**：

```
缺 1 句 → 整包重打（40 句進、40 句出）
仍缺   → 切半分治（兩個 20 句包，各自可能再重試）
禁用詞 → 整包再打一次
```

修稿 pass 也有同款浪費：**44/274 句真的被改**，卻要求模型回傳全部 274 句。

## 3. 修法（依「對帳單的影響」排序）

### L1 — 補丁式重試（最大槓桿，output 側）

第一輪之後只把**缺的那幾句**單獨包成小請求補翻（帶前後文當語境，但只要求輸出缺句）。

- 觸發條件：缺句數 ≤ max(3, 25% of chunk) → 走補丁；**大量缺句仍走切半分治**
  （那通常是輸出截斷，補丁救不了）
- 禁用詞重打同理：只重譯命中的那幾句，不是整包
- 預估：這支影片的重試輸出 ~17k tokens → ~3k，**省 ~NT$3.8**

### L2 — 修稿只回傳「有改動」的句子（output 側）

prompt 改為「只輸出你有修改的句子，沒改的不要回」，合併時未回傳的沿用原文。

- 附帶好處：修稿 diff 變得**可稽核**（現在無法分辨模型改了什麼 vs 原樣照抄）
- 風險：模型可能偷懶少改 → 用 `asrRepaired` 計數與抽樣比對監看（既有欄位）
- 預估：修稿輸出 ~4.1k → ~0.7k，**省 ~NT$0.95**

### L3 — glossary 子集化（input 側，效益小但幾乎零風險）

翻譯 chunk 只帶「該 chunk 文字裡真的出現」的術語（term 變體比對沿用
`attachGlossaryNotes` 的 `/` 拆分邏輯），不是全表照抄每個 chunk。

- 實測該片 glossary 18 條 ≈ 530 tokens/呼叫，佔單次 prompt 約 35%
- **但輸入只佔帳單 20%** → 預估只省 ~NT$0.28。列為順手做，不值得單獨排

### L4 — 禁用詞表延後（input 側，最小）

第一輪不送 16 條對照表，命中掃描後才在重試 prompt 帶上。
（品質地板不變——執法掃描本來就在程式端。）預估 NT$0.1 級，最後再考慮。

**合計預估：NT$10.87 → ~NT$5.8（-47%）**，其中 L1 一項就佔了 ~35pp。

## 4. 不做的事

- ❌ **砍重試次數**：重試是品質地板的一部分（缺句 → 顯示原文是可見的失敗）。
  我們要的是「同樣的保證，更便宜的實現」，不是降低保證
- ❌ **關掉修稿 pass**：日文實驗證明它修好了 `Zold8`→`Z Fold8`（產品名正是 ASR 的系統性錯誤）
- ❌ **換 lite 級模型**：已實測否決（E 組，見 model-experiment.md）

## 5. 驗收 Gates

用本機 `worker/scripts/ab-runner.ts` 跑（不碰 production、不影響帳單），
兩支固定樣本：`hK9fypJKHyY`（英文 ASR 274 句）、`9gHJwbSHPus`（日文 ASR 679 句）。

| # | 驗收 |
|---|---|
| G1 | 兩支的 `untranslated` **不得增加**（目前皆 0）|
| G2 | `warnings` 不得新增類別；禁用詞殘留不得增加 |
| G3 | tokens 總量下降 ≥ 30%，且 output 佔比下降（證明省到的是貴的那半）|
| G4 | 抽樣 10 句人工比對，補丁回來的句子與整包翻的品質同級（**補丁不得產生上下文斷裂**）|
| G5 | 修稿 diff 可稽核：`asrRepaired` 與實際改動句數一致 |

## 6. 工作量

| 件 | 估計 |
|---|---|
| L1 補丁式重試（`translateChunk` 改造 + 測試）| 半天 |
| L2 修稿只回改動（prompt + 合併邏輯 + 測試）| 2–3 小時 |
| L3 glossary 子集化 | 1 小時 |
| A/B 驗證兩支樣本 + 回填數據 | 1 小時 |

## 7. 實測結果（2026-08-14 實作後，本機 ab-runner 跑 hK9fypJKHyY）

| | 舊（production）| **新（L1+L2）** |
|---|---|---|
| tokens | 78,176 | **42,172（-46%）** |
| ├ prompt | 47,289 | 27,717 |
| └ output | 30,887 | **14,455（-53%）** ← 貴的那半 |
| LLM 呼叫 | 31 | 21 |
| 重試 | 12 | 6 |
| **估算成本** | NT$10.87 | **NT$5.35（-51%）** |
| untranslated | 0 | **0** ✅ |
| warnings | 1（缺 1 句）| **0** ✅ |

G1–G3 全過，且**品質不降反升**（缺句 warning 消失）。實際節省略優於預估的 -47%。

### 8. 過程中發現的既有問題：子句邊界漂移（不是本次改動造成）

G4 抽樣人工比對時發現：長原文配極短譯文（例 `I think it is a very good option for a` → 「它的」），
連續數句的譯文相對原文**整段位移一格**。

**歸因（零成本比對，非猜測）**：掃描新舊兩份輸出的同款異常 —— **舊版 3 句、新版 5 句**，
兩邊都有 → **既有現象，不是 L1/L2 引入的**。成因是 ASR 句子本身是碎片，
模型把子句邊界跨 cue 重新分配（語意總和正確，但單句對位會漂）。
新舊差異（3 vs 5）在 n=1 下**不足以下結論**（見 gemini-api-lessons §2 的 A/B 方法論：
先量同設定的自然變異，再談差異）。

**已做**：加 deterministic 偵測（`driftSuspect`：原文 ≥6 詞、譯文 ≤4 字），
計數進 `hints`（僅提示，不觸發重譯 —— 短譯文也可能是合理的）。**可見的問題優於沉默的問題。**

**未做（future idea）**：真要根治得上「回聲對位」——要求模型每筆回傳原文前 8 字，
對不上就丟棄該筆（sukemu 的做法，見 gemini-api-lessons §6）。代價是每句多付幾個 token，
且需要同設定重複 3 次量出自然變異才能驗證有效性。
