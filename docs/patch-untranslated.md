# 未譯句：事後自動偵測 + 補譯（P1–P3）

> 起因：2026-08-16 使用者在 player 上看到三句日文沒翻成中文。
> 系統其實**知道**（`untranslated: true` + warnings 都記了），但那些資訊只躺在
> `bilingual.json` 裡 —— 使用者是「看片時才發現」。
> 這份計畫要把它變成：**翻完就自己檢查、自己補、補不完才讓人看到**。

## 1. 病因解剖（實例：`JM-oaFXgaSg`，119 句中 3 句未譯）

| 未譯句 | 病因 | 該怎麼修 |
|---|---|---|
| `かと一緒に来るっていうことが` | 模型**已翻好**（`"zh":"和誰一起來這件事"`），但輸出多一個 `}` → 整包 JSON 解析失敗 | **P0-a 物件級救援**：陣列解析失敗時逐個 `{…}` 撿回來，別把付過錢的譯文丟掉 |
| `え、イメージはあります。…` | 同一包被牽連 | 同上 |
| `。` | 整句只有一個句號，**沒有東西可翻**；還被回聲對位擋下（`t=「。」` 正規化後是空字串） | **P0-b 不可翻句預過濾** + **P0-c 回聲不可判斷時放行** |

另外查 `kCIvgJklMWQ`（512 句）發現 `sanityCheckItem` 對**無空格語言失效**：
它用 `split(/\s+/)` 數詞數，日文一整句只算 1 個「詞」→ 4 詞門檻永遠不成立 →
「原文照抄」「沒有中文」兩道檢查對日文/韓文形同虛設。

## 2. 設計

### P0：讓未譯句一開始就少發生（deterministic，零額外成本）

| 修法 | 位置 | 說明 |
|---|---|---|
| a. 物件級救援 | `cleanJson` | 陣列整體解析失敗 → 掃出所有平衡的 `{…}` 逐個 parse，撿回可用的。付過錢的輸出不該因為一個逗號全丟 |
| b. 不可翻句預過濾 | `translatableSentence()` | 沒有任何字母/漢字/假名的句子（`。`、`♪`、`...`）不送模型、直接沿用原文，也**不算未譯** |
| c. 回聲不可判斷放行 | `echoMismatch` | 正規化後的 `t` 不足 3 字 → 無法判斷 → 放行（原本「空字串」是直接判定不符，與 `n < 3` 放行的規則自相矛盾）|
| d. 無空格語言的品質檢查 | `sanityCheckItem` | CJK 用字數估「詞數」；「沒有中文」改成**只認漢字**（假名不算）；加假名比例 > 50% 的攔截 |

### P1：翻完自動補譯（`patch` 步驟）

```
assemble → （untranslated > 0 且補譯輪數 < 2）→ patch → 更新 bilingual.json
```

- 目標句 = `untranslated === true` **或** `zh === orig`（≥6 字才算，短句本來就可能一樣）
- 只送這幾句 + 前後各 2 句語境（沿用 L1 補丁式重試的作法），成本以「句」計不是以「片」計
- 補完重寫 `bilingual.json` / `.srt`，更新 warnings 與 `status.untranslated`
- **上限 2 輪**：補不動的句子就是補不動（多半是原文本身有問題），不無限燒
- 走 queue consumer → 四層保險絲全部適用

### P2：看得見

- `status.json` 加 `untranslated` 欄；`/jobs.json` 帶出來
- `/admin` 每列顯示「⚠ N 句未譯」，旁邊一顆 **✏ 補譯** 按鈕（同 ⏱修時間 的位置）
- `POST /patch/{videoId}`（key 認證）：手動觸發同一個步驟

## 3. 驗收

- 單元測試：物件級救援、不可翻句、回聲放行、日文 `sanityCheckItem`、補譯目標偵測
- 端到端：塞一份含未譯句的 `bilingual.json` → 跑 patch → 未譯歸零且時間軸不變
- 實測：對 `JM-oaFXgaSg` 執行補譯，三句應該補回 2 句（`。` 那句會被 P0-b 濾掉，不再算未譯）

## 4. 不做

- **不自動重跑整支影片**：補譯只補句，重跑整片要人明示（`?force=1`）
- **不靠 LLM 判斷「翻得好不好」**：偵測一律 deterministic（開發原則 #1）
- **不無限補**：2 輪就停，剩下的照舊標 `untranslated` 讓人看得見

## 5. 決策

```
決策：做（2026-08-16）— 使用者看片時才發現未譯，等於品質防線沒有出海口
日期：2026-08-16
```

## 6. 實測（2026-08-16，拿 production 真實資料跑）

用 `JM-oaFXgaSg` 的真檔（bilingual/sentences/glossary/status）在本機跑 `patch` 步驟：

```
補譯前未譯：['かと一緒に来るっていうことが', 'え、イメージはあります。その一方もう1', '。']
結果：{"ok":true,"patched":2,"left":0,"round":1}

#18 かと一緒に来るっていうことが
   前：かと一緒に来るっていうことが（untranslated=true）
   後：跟某個人一起來這裡的畫面。
#35 え、イメージはあります。その一方もう1
   前：え、イメージはあります。その一方もう1（untranslated=true）
   後：我腦海中大概有這樣的畫面。但另一方面，另一種
```

- 兩句補回、`left: 0`、`status.untranslated` 歸零
- 第三句 `。` 被 P0-b 正確排除（沒東西可翻 ≠ 翻譯失敗），不再算未譯也不再送模型
- 一次補譯只花一次 API 呼叫（幾百 token，NT$0.1 以下）

**上線後對既有影片的處理**：`/admin` 那列會出現「✅ done ⚠ N 句未譯」與 **✏補譯** 鈕，
按一下就補；之後翻的新片會自己補，不用人管。
