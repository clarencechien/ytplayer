# 播放畫質計畫（iframe 720p 的成因與兩條出路）

> 狀態：**計畫，未實作**。決策欄在 §7。
> 起因：2026-08-14 觀察到 player 內預設 720p、最高 1080p，但同一支片在 youtube.com
> 可以 1080p 加強版甚至 4K。

---

## 1. 診斷：三個機制疊起來，不是單一「iframe 上限」

| 機制 | 說明 | 我們能不能動 |
|---|---|---|
| **ABR 跟播放器渲染尺寸走** | YouTube 依播放器實際尺寸選畫質：720p 需 ~1280×720、1080p 需 ~1920×1080。我們的 player 右側逐句稿吃掉寬度，影片區在多數螢幕上**達不到 1280×720** → 落 720p | ✅ **可以**（把影片區做大）|
| **畫質 API 已失效** | IFrame API 的 `setPlaybackQuality()` 官方標為 deprecated、無作用；`vq` URL 參數非官方支援（網路上「還能用」的多是舊文）| ❌ 不能靠程式指定 |
| **1080p 加強版 / 4K 綁登入 + Premium** | 那是 Premium 功能，要**登入**才有。iframe 內的 YouTube 屬第三方情境（Safari 全封第三方 cookie、Chrome 限縮）→ 嵌入播放器通常是**登出狀態** | ❌ iframe 架構內無解 |

**結論**：720p 是預期行為。第一項有救（也是最有感的），第二三項在 iframe 裡是死路。

## 2. 動手前先量測（本專案慣例：先有數據再談修法）

Player 加一段臨時 debug 輸出（或直接 console 手測），記錄：

- `document.getElementById('player').getBoundingClientRect()` — 影片區的 CSS 尺寸
- `window.devicePixelRatio` — HiDPI 螢幕上 CSS 1280 ≠ 裝置 1280，**這點會影響門檻判讀**
- `yt.getPlaybackQuality()` / `yt.getAvailableQualityLevels()` — 當下畫質與可選清單
- 三種情境各量一次：**預設版面 / 收起側欄 / 全螢幕**

**驗收前提**：若「收起側欄」與「全螢幕」量到的畫質沒有提升，§3 的 A 案就不成立，
直接跳 B 案或收工——不要先做再說。

## 3. A 案：劇場模式 + 畫質可見（小、低風險）

1. **劇場模式**：熱鍵 `T`（YouTube 慣例）切換隱藏右側逐句稿 → 影片區吃滿視窗寬度，
   跨過 1280×720 / 1920×1080 門檻。狀態存 localStorage（與既有設定同一套）
2. **畫質顯示**：資訊列顯示 `getPlaybackQuality()` 的結果（`hd1080` / `hd720`…），
   切換版面後即時更新——讓「有沒有變好」看得見，不用通靈
3. 既有逃生口不變：「YT 介面：開放」後可直接點原生齒輪手動選（選單裡仍不會有 Premium 檔位）

工作量：約 1 小時。風險：低（純前端版面，不動資料與 pipeline）。

## 4. B 案：ext 在 youtube.com 原生頁疊字幕（架構級）

iframe 拿不到 Premium/4K，唯一的出路是**不要用 iframe**：讓 ext 直接在 YouTube 原生頁面上
疊我們的雙語字幕層。

**為什麼對我們特別可行**：ext 已經在 youtube.com 有 MAIN world 存取權、已經在攔截字幕請求——
多做的只是「抓 `<video>` 的 currentTime → 對照我們的 bilingual.json → 注入字幕 DOM」。

| | iframe player（現行） | ext 原生疊層（B 案）|
|---|---|---|
| 畫質 | 720p/1080p 上限、登出狀態 | **原生**（Premium 1080p、4K、你的帳號設定）|
| 平台 | 桌機 + 手機（PWA 規劃中）| **僅桌機 Chrome**（有 ext 的環境）|
| 字幕功能 | 完整（雙語/譯註/字卡/熱鍵/透明度）| 要重做一套（或裁剪成精簡版）|
| 維護 | 一套 | **兩套渲染** |

**設計要點（真做的話）**
- 資料來源：ext 直接 `fetch` 我們的 `/subs/{id}/bilingual.json`（已公開可讀）
- 同步：監聽原生 `<video>` 的 `timeupdate`（比我們 iframe 的 150ms 輪詢更準）
- 版面：字幕層插在播放器容器內、`pointer-events: none`，全螢幕時跟著進去
- 原生 CC 要關掉（避免雙層字幕）——注意這與現行 player 的 `killNativeCC` 是不同機制
- 功能先做子集：雙語顯示 + 字級 + 開關（C 鍵）。譯註/字卡/逐句稿留在 player 頁
- 風險：**YouTube 版面改版會打壞注入點**（比 iframe API 脆弱），要有選擇器失效時的靜默降級

工作量：一天級（含改版脆弱性的防禦）。**建議只在 A 案量測後仍不滿意才做。**

## 5. 不做的事

- ❌ `vq` URL 參數 / `setPlaybackQuality()`：官方已無作用，靠它等於建在流沙上
- ❌ 想辦法讓 iframe 帶登入狀態拿 Premium：與瀏覽器第三方 cookie 政策對抗，且會隨政策再壞一次
- ❌ 自行下載/轉存影片流：紅線外（我們只處理字幕，不碰影片本體）
